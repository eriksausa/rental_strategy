# Walk-forward forecasting & elasticity report

> **Synthetic data.** Everything below is computed on the synthetic demo panel (`src/rental_engine/synthetic_panel.py`). It describes the generator, not the real market. The private operating data used in the original analysis is not part of this repository.

Generated by `python scripts/run_forecast_pipeline.py`. Reproducible: fixed seeds, no network access.

## Setup
- Panel: 12 units x 48 months (last observed month 2025-12).
- Rolling-origin backtest: origins 30..46 (month index), forecast horizons 1..12 months, 1,656 out-of-fold unit-month forecasts per model and target.
- At each origin, models are trained only on pairs whose target month was already observed (no look-ahead).
- Model chosen per target by lowest overall RMSE on the transformed scale: ADR = **Gradient boosting**, occupancy = **Unit x calendar-month mean**.

## Backtest results (all horizons)

### Nightly ADR
| Model | MAE (MXN) | RMSE (MXN) | Skill vs best baseline |
|---|---:|---:|---:|
| Seasonal naive (same month last year) | 439.74 | 553.51 | -5.5% |
| Seasonal naive + recent YoY drift | 451.99 | 576.44 | -3.2% |
| Unit x calendar-month mean | 421.58 | 530.61 | +0.0% |
| Random forest | 443.15 | 551.30 | -3.5% |
| Gradient boosting | 414.40 | 524.78 | +3.4% |

### Monthly occupancy
| Model | MAE (occupancy pts) | RMSE (occupancy pts) | Skill vs best baseline |
|---|---:|---:|---:|
| Seasonal naive (same month last year) | 11.20 | 14.63 | -23.9% |
| Seasonal naive + recent YoY drift | 13.52 | 17.33 | -48.0% |
| Unit x calendar-month mean | 9.31 | 11.83 | +0.0% |
| Random forest | 10.51 | 13.03 | -9.9% |
| Gradient boosting | 10.19 | 12.68 | -6.8% |

Occupancy noise floor: even a forecaster that knew the true latent occupancy probability would have a MAE of about **6.8 points**, because observed occupancy is a count of nights out of ~30. Errors close to that are as good as this data allows.

**Reading this honestly:** on a small panel whose structure is seasonality plus unit effects plus unforecastable shocks, a unit x calendar-month average is hard to beat. Positive skill means the model beat the best baseline; negative means it did not.

## Uncertainty used by the Monte Carlo
- Out-of-fold residuals of the chosen models are saved (`artifacts/oof_residuals.csv`).
- Mean residual removed before bootstrapping (transformed scale): ADR +0.160, occupancy +0.011. Centering keeps the bootstrap from importing a bias specific to the backtest window.
- The simulator resamples WINDOWS of consecutive-horizon residuals (block bootstrap), so the dependence between ADR and occupancy errors, and any month-to-month persistence, are taken from the backtest instead of being assumed away. In this synthetic panel the ADR/occupancy error correlation is negative by construction (discretionary price changes lower occupancy), which narrows the revenue distribution; real data may differ. `python scripts/demo_uncertainty.py` shows the effect on one decision.

## Price elasticity of occupancy
Model: logit(occupancy) = fixed effects + beta * log(ADR). The generator's true beta is **-1.6**.

| Specification | Estimate of beta |
|---|---:|
| Naive pooled OLS | 1.059 |
| Unit + calendar-month + trend controls | -0.997 |
| Unit + year-month fixed effects | -1.097 |
| **Unit x calendar-month + year-month fixed effects** | **-1.703** (95% CI -1.991 to -1.399) |

The naive regression has the wrong sign: high-season months have both high prices and high occupancy, and market-wide demand shocks push both up. Absorbing unit-specific seasonality and every market-wide shock recovers the true value. At the panel's mean occupancy (54%) the implied price elasticity of the occupancy rate is about -0.79.

## Limitations
- Synthetic data: the generator is simple (seasonality, unit effects, one market shock). Real markets have events, competitor supply, and lead-time effects that are not modelled.
- Elasticity is identified from each unit's deviations from its own seasonal price pattern after removing market-wide shocks; in real data, those deviations may still respond to unobserved demand.
- Residual blocks come from one backtest run; with real data, use more history and check stability.
